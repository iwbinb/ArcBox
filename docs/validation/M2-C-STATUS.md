## 2. 原阻塞与修复

先前提交 `fdcef71` 的 [CI 36219852593](https://github.com/iwbinb/ArcBox/actions/runs/36219852593) 在浏览器 UI-08 失败：日志列表预期 25 条，读取时为 0；随后拍摄的失败截图已经出现日志。后端 58 项当时通过，但不能因此把浏览器验收算作成功。

定位到页面加载状态竞态：会话刷新与列表读取共用 loading 标记；切换标签后的首个渲染可能沿用旧的“加载完成”，会话请求的 finally 也可能提前结束尚未完成的日志读取。仅增加等待秒数不能修复用户界面的错误状态。

修复位于 `apps/web/src/platform/useOperations.ts`：

- 以当前身份、工作区、标签和递增版本组成 viewKey；只有属于该次视图的请求完成，才更新 settledView。新视图在首个渲染即为 pending，不等待 effect 才补上加载状态。
- 会话初始化状态与列表状态分离；会话刷新不能将未完成列表标为已加载。
- epoch、请求序号及 effect cleanup 拦截旧响应。切回早先标签也生成新版本，不能复用旧完成标记。
- 分页保留已加载记录，且不能把旧视图的迟到分页结果追加到新视图。
- 保留已实现的退出响应与新登录串行处理，避免旧 Set-Cookie 删除覆盖新会话。

UI-08 现在先获取真实 Worker 的日志响应并暂缓送达浏览器，再触发会话刷新：列表必须仍显示忙碌，不出现“暂无记录”。释放真实响应后精确校验首屏 25 条、加载更多后完整顺序与 API 一致；本次实测 **38 条**。这不是用假数据替换接口响应。

新增 UI-08b 故意将旧日志响应晚于标签切换释放；新文件请求未完成时不得被旧响应提前结算或覆盖。UI-09/10 也已实际执行，验证只读角色、钱包变化、语言和撤销会话。验收脚本强制检查 11 个场景及关键名称，不允许跳过失败用例或复用旧报告。

## 3. 完成的功能

| 能力 | 交付内容 | 安全边界 |
|---|---|---|
| 受控文件 | 上传会话、不可变版本、R2 条件创建、大小/MIME/哈希校验、隔离与 READY 状态 | 当前只有两份审核过的纯文本样本；不接受任意上传，不宣称病毒扫描 |
| 规则与文件绑定 | 文件 ID、版本、内容哈希与访问保留期冻结进规则；追加独立迁移 | 旧规则不能事后更改内容或绑定 |
| 私有下载 | 订单派生权益、短期单次凭证、会话/钱包绑定、R2 读取后最终权限校验 | 退款、撤销、到期、来源暂停即拒绝新访问；不能回收已下载副本 |
| 异步任务 | outbox 桥接、真实本地 Queue 分发/消费、去重、租约、重试与死信 | 消息只带受限 ID，实际内容从数据库读取；不执行任意任务或 URL |
| 手动恢复 | owner/operator 按版本重试 DEAD 任务；generation 防止旧消息污染新重试 | 不允许强制批准完整性失败文件，也不重复付款 |
| 站内通知 | 由已核验的订单事件生成，按用户隔离并可标已读 | 历史通知不代表订单当前状态；没有外部邮件/Webhook |
| 操作与恢复页 | 文件、任务、通知、日志分页、订单当前分类与下载；中英文/移动端 | 沿用 SIWE、角色与跨工作区访问控制；无管理员改余额或已付款入口 |

详细 API、权限、限额与本地操作见 [M2-C 操作说明](M2-C-OPERATIONS.md)。

## 6. 复现命令

在仓库已验证的 Linux x64 环境，使用 `.node-version` 与 `packageManager` 指定版本：

```bash
pnpm install --frozen-lockfile
pnpm setup:arc
pnpm verify
```

单项：`pnpm test:platform` 运行 58 项后台测试；`pnpm verify:platform` 包含平台类型、运行时、页面构建、Worker dry-run 和浏览器验证，需要已安装 Chrome 与中文字体。完整 `pnpm verify` 会先运行既有身份浏览器准备流程。机器结果位于 `reports/m2-c.json`、`platform-tests.json`、`platform-browser.json`，截图哈希随报告验证。不要把 `wrangler deploy --dry-run` 写成实际部署。
