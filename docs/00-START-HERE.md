## 1. 已明确的项目边界

用户确定：项目叫 ArcBox；是工具集合站而非单个支付应用；六工具必须深度设计；要有具体用户场景；不需要与 NodeStake 关联；文档进入 iwbinb/ArcBox。Cloudflare 为首选部署平台。

本包提供开发规格，不宣称已编写或运行产品。视觉风格、价格、时限、试运行额度、阶段顺序是本版设计决策，均可以在开发前调整；调整资金条款必须版本化，不能追溯改变已付款订单。

## 2. 产品一句话

“选择用途，设置规则，发布链接。”用户能卖数字商品、发起成团、分配收入、管理报名保证金、按阶段收款、发放奖励；每项独立可用，共享可信的支付/退款/权限基础。

## 4. 基线决策摘要

- 一套网站、一个账户体系、可创建多个工作区；一个钱包在不同工作区的权限不同。
- 英文和简体中文界面；默认按语言偏好，无法判断时英文。文档中文为主，标识/API 英文。
- 网站为“工具目录 + 场景介绍 + 创建向导 + 管理后台 + 参与者记录 + 公共操作页”。
- 基线支付资产只支持 Arc ERC-20 USDC；不做多币种或跨链结算。
- 六种业务合约实例隔离，不做万能可升级资金池。分账只接收已经不可退款的结算款。
- 所有时间条件由合约时间执行；网站倒计时和 Cron 不决定用户是否拥有退款权。
- 试运行平台费 0；链上 Gas 仍由调用者支付。不把未来订阅收费提前写入合同。
- 合约暂停只针对创建/新增入金；正常退款、已形成的固定权益领取保留。

## 5. 规格的严谨程度与限制

本包是行为与接口设计，不是经过审计的 Solidity 实现。数据库表是逻辑设计，不是直接可执行的迁移；路由/API 是实施契约，不是已上线接口。未提供真实生产域名、资金地址、部署者、仲裁方、RPC 商业套餐或商标核验结果。

出现冲突时：用户明确指令 > 最新已批准 ADR > 资金安全不变量 > 对应工具的业务规格 > 公共页面示例。不要通过放宽安全规则消除冲突，必须记录并修订。

## 6. 交付顺序不等于删减范围

完整六工具均须保留规格与验收。可先交付 Split/Deliver/Group 的主网小额版本，随后完成 Rewards、Attend、Milestones。后两项依赖现实世界事实和争议处理，不应在责任人、时限、证据流程尚未确定时开放资金入口。
