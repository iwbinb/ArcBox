# 02 · 网站结构与用户体验

## 1. 全站原则

目录优先，不做单个支付 SaaS 的宣传页。普通访客先理解用途；创建者有工作区；买家只看到自己的订单。钱包连接不是浏览的前置条件，注册工作区不是付款的前置条件。

一级导航：**工具 / 使用场景 / 我的记录**；右侧 **语言、连接钱包 / 工作区**。产品顶部可有小字 Built on Arc，但明确为独立项目，不暗示 Arc 官方产品。

## 2. 路由地图

| 路由 | 访问 | 内容 |
|---|---|---|
| / | 公共 | 工具集合首页，按偏好显示中/英文 |
| /tools | 公共 | 六工具目录、搜索、分类 |
| /tools/:tool | 公共 | 场景、流程、规则、示例、创建 CTA |
| /use-cases/:slug | 公共 | 课程/数字商品/合作/活动等组合说明 |
| /demo | 公共且隔离 | 带永久 Demo 标识的合成数据，不连接主网资金 |
| /create/:tool | 登录后可保存 | 创建向导，支持未登录临时草稿但不自动跨设备同步 |
| /app | 工作区成员 | 待处理事项与最近项目 |
| /app/projects | 工作区成员 | 六工具实例的统一列表 |
| /app/projects/:id | 基于角色 | 项目详情、参与记录、资金、设置版本 |
| /app/activity | 基于角色 | 业务活动与链上证据，不是通用区块浏览器 |
| /app/files | 编辑及以上 | 文件版本、占用、保留期、交付引用 |
| /app/team | owner | 邀请/移除成员，链上角色另行确认 |
| /app/settings | 基于角色 | 语言、通知、API/Webhook（后续）、默认展示资料 |
| /me | 钱包登录 | 我的购买/报名/领取/阶段付款/分账，跨工作区聚合 |
| /p/:slug | 公共 | 发布链接；底层 toolType 决定公共模板 |
| /r/:orderId | 当事钱包 | 付款凭证与下一步，未登录只展示非敏感摘要 |
| /claim/:campaignId | 公共查询 + 签名 | 奖励资格及领取 |
| /recovery | 公共 | 合约地址、规则、官方链浏览器入口、自助恢复说明 |
| /help、/status、/legal/:page | 公共 | 操作说明、服务状态、真实政策 |
| /ops | 内部 | Access + 应用 RBAC 双重保护的运维页 |

语言用持久偏好与 i18n key，不更改订单 ID、合约地址或时区事实。SEO 页面可生成 /en、/zh 规范别名，避免共享链接依赖语言。相同业务数据不按语言复制。

## 3. 首页层级

第一屏从上到下：轻导航；标题“你今天想完成什么？”；一句定位；工具搜索；六工具 3×2 网格。卡片格式严格统一：图标、中文用途/英文短名、一个任务句、真实状态、主按钮。

下方：一条“成团→交付→分账”组合示例；三步使用说明；费用/安全边界；FAQ。无虚构客户 logo、交易量、收益数字、获奖标识。未上线工具保留入口但 CTA 是“查看方案”，不是可付款按钮。

推荐分类：收款与交付（Deliver、Group、Milestones）；资金分配（Split、Rewards）；活动管理（Attend）。六项规模下不使用复杂多层筛选，搜索可识别“退款、发文件、开课、奖励”等场景词。

## 4. 创建者旅程

选工具 → 看具体例子与责任 → 连接钱包并 SIWE 登录 → 创建/选择工作区 → 向导填规则 → 检查公开页 → 钱包确认部署/发布 → 获得链接 → 管理订单 → 完成结算。

创建前可浏览所有字段。草稿保存成功有时间与版本；切换钱包时重新校验 owner；离开脏表单提示保存。与已发布对象同名的新草稿不能覆盖旧链上版本。

公开页预览必须同时展示桌面/手机布局以及“对方会看到什么”，但不使用伪交易填充。金额、退款条件、受益人、截止时间、网络、平台费、Gas 责任均在发布检查中明示。

## 5. 参与者旅程

打开分享页 → 无登录先看规则 → 连接钱包 → 网络/余额/Gas 校验 → 如需精确授权则批准 ERC-20 → 确认业务交易 → 区分链上已确认和服务处理中 → 获得权益/后续操作。

不要把“授权 USDC”写成“已付款”。拒签不是支付失败事故；允许关闭、恢复。用户关闭网页后重新从 /me 或订单链接恢复，不应再付一次。

## 6. 工作区权限

| 角色 | 业务权限 | 资金权限 |
|---|---|---|
| owner | 成员、所有草稿、策略和导出 | 仅当其钱包同时是合约指定角色；RBAC 不能代替链上授权 |
| editor | 商品/活动文案、文件、草稿 | 无自动资金权限；发布重要条款需 owner 签名 |
| operator | 订单查看、签到、有限通知 | 只有另行授予的签到证明权限，无任意放款 |
| viewer | 脱敏只读 | 无 |
| participant | 自己的记录 | 按合约拥有自己的付款/退款/领取权 |
| resolver | 仅被指定的争议与证据 | 只能在约定范围/时限分配对应锁定款 |

从团队移除成员不能追溯更改其已确认的 Split 收益或已付款订单；未来操作权限与旧资金权利明确区分。

## 7. 移动端

375px 起保证完整关键路径。目录单列或两列短卡片；工作区侧栏变抽屉；桌面右侧操作面板变底部摘要与单主按钮。合约地址可换行、复制，表格变键值列表。签到页单手使用、大按钮、相机权限失败有人工码回退；离线签到只显示“待核验”，不显示已退款。

## 8. 空态与失败导航

首次进入 /app：解释创建首个项目，提供六工具入口；不是空图表。/me 未连接钱包：解释仅查看此钱包记录。没有符合资格的奖励：显示查询钱包、网络和资格规则，不泄露其他名单。

索引落后时显示“链上已确认，正在同步”及交易链接；RPC 不可用时显示“暂时无法核验，请勿重复付款”。全站不可用仍应能通过 /recovery 的可保存说明与合约直接交互；文件与未保存 Merkle proof 仍有链下可用性限制。
