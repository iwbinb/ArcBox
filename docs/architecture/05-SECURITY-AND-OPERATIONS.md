# Architecture 05 · 安全、隐私与运维

这是威胁模型和门禁，不是已完成审计。风险控制旨在降低损失面，不能保证零风险。

## 1. 资产与边界

保护资产：用户本金与credit、工作区权限、固定规则/签名、付费文件、奖励名单、仲裁证据、部署/证明密钥、RPC/存储凭证。攻击者可控制浏览器、请求、上传文件、恶意代币调用、队列重放、社交资料；也要考虑工作人员误操作、业务签名服务被攻破、Cloudflare账号被接管和RPC错误。

## 2. 威胁表

| 风险 | 预防/限制 | 检测与恢复 |
|---|---|---|
| 假交易解锁 | chainId/实例/业务事件/payer/amount/version完整校验 | 隔离错误receipt，不标已付款 |
| USDC重复记账 | 只以业务事件驱动订单，Transfer仅对账 | 比对原始事件和ledger唯一键 |
| 浮点/舍入错误 | bigint、固定6位、bps和dust显式 | 向量与不变量模糊测试 |
| 并发重复退款/分账 | 合约终态/nonce/bitmap、CEI、重入保护 | 守恒对账，停新入口 |
| 签名重放 | 712域+chain+实体+nonce+expiry+状态版本 | 消费记录与失败频率告警 |
| 工作区越权 | 每层对象归属核验，不只查顶层workspace | 双账号IDOR测试、审计日志 |
| 盗用下载链接 | 短期授权、no-store、最小暴露、权限撤销 | 访问异常限流，承认已下载不可回收 |
| 恶意上传 | quarantine、扫描/人工批准、MIME/大小/hash | 隔离文件，停新售卖，不夺取退款 |
| CSV/表格公式注入 | 导入严格schema，导出安全转义 | 样例攻击文件测试 |
| 工作人员错签到 | 有限角色、一次挑战码、补录审计 | 缺席挑战期，超时全退 |
| 仲裁方离线 | 明确固定裁决期/预先确认兜底规则 | 时间到独立退出，不能永远冻结 |
| 代执行密钥泄露 | 只限白名单动作/小Gas余额/独立账户 | 停签名、停新单、轮换未来版本 |
| RPC/索引异常 | 备用RPC、持久cursor、业务事件重放 | 不一致fail closed，展示已知证据 |
| Queue/D1部分失败 | 事务outbox、消费者去重 | 重放不重复资金/交付 |
| 构建供应链 | 锁版本、PR审查、Secrets隔离、构建产物核验 | 回退Web版本，复核前端交易目的地 |

## 3. 密钥分层

用户私钥永不经过ArcBox。合约管理/部署者不与业务attestor或Gas钱包复用。业务签名密钥可以置于受限服务秘密或经核验远程签名服务，但代码必须限制可签内容；不提供“传任意JSON我来签”。签名域不同不能共用宽松验证器。

泄露attestor可能谎报文件可用/签到，不能改付款人和固定退款条款。泄露Gas账户损失只应限其预算，不应赋予资金转移权限。key rotation只影响新版本；已有实例如何完成证明或退款需要在停用前列出，不承诺能即时替换所有旧合约角色。

## 4. 危险管理员功能禁止清单

禁止“把订单设成已付款”“修改可领取余额”“重置已领取位图”“将旧收款地址换成管理员”“将未领本金全部归平台”“跳过成员/双方同意”“延长用户挑战期限同时冻结其提现”。

运营后台只做有日志的任务重放、可见性下架、停止新增、查看脱敏证据索引、角色管理。任何资金结果仍必须来自合约授权动作；后台不能生成自创财务事实。

## 5. 隐私与内容

姓名、邮箱、名单标签、争议内容、下载URL、会话、私钥不写到链上或公共仓库。hash不是保密措施，低熵数据需随机盐且原文私有。奖励root/领取交易仍可能泄露关系，不承诺匿名。

订单当事人看到自己的资料，resolver仅访问指定争议证据，support默认只看元数据。公共页面安全Markdown清洗、外链标记、上传内容不执行。禁止/投诉流程由实际运营者确定，尚无真实客服域名时不能编造。

保留政策必须与用户承诺和必要义务协调。建议日志30天、文件至少覆盖已承诺访问期、争议证据覆盖裁决和经审阅的后续保留期；具体期限不是法律结论。用户删账户不改变公开链交易，但应删除/匿名化不再必要的链下PII。

## 6. 暂停与事故流程

触发：不变量差异、错误网络/地址、签名泄露、异常结算、代执行失控、关键文件/proof丢失。行动顺序：

1. 停新实例、付款intent和危险证明签发；向用户显示维护原因。
2. 保留已定义的安全退款/领取入口、只读合约与证据；不随意延长时限。
3. 保存日志/commit/交易hash，核对影响实例和剩余负债。
4. 修复链下服务并演练；若是不可升级合约漏洞，不声称前端升级已修复合约。
5. 公布事实、影响、已采取动作和未解决风险；新实例采用新版本，旧实例按原可用退出路径处理。

不可升级合约减少管理员变更风险，也意味着漏洞修复受限；此取舍必须披露。任何紧急冻结设计变化必须另行审查，不能作为偷偷控制用户资金的后门。

## 7. 运维目标与告警建议

以下为内部告警阈值建议，不是服务保证：交易快速核验超过30秒告警提示；索引落后超过2分钟提示、10分钟停新资金入口；Deliver证明剩余不到5分钟仍未提交为高优先；outbox最旧5分钟告警、DLQ有消息告警；RPC返回错误chainId立即隔离。

Gas预算不足停止需要自动证明的新订单。按日比对每实例链余额、locked/credits、已外部结算、异常surplus，出现差额不通过数据库补数掩盖。通知发送不参与资金正确性判定。

## 8. 恢复演练

必须测试Worker重启、D1恢复到旧备份、Queue重复/丢ACK、R2对象缺失、RPC切换、attestor失效、成员USDC转出失败、争议方失联。演练记录当前commit、步骤、实际结果和未解决项，不只截一张首页运行图。

恢复时重放链事件到新投影版本，比较资金账；已发送邮件允许再次核对但不得重复解锁已撤销权限。个人恢复包及Rewards proof需要独立校验，不只依赖后台在线。

## 9. 主网门禁

源代码/依赖版本锁定；关键路径真实测试；权限与资金不变量通过；独立安全审查和严重问题清零；实际角色/联系渠道/争议服务确定；适用地区、商品权益、退款和托管责任经审阅；风险限额与告警配置；真实小额入金→退款/结算/领取→余额核对；用户明确授权主网操作。

没有审查预算时可以交付testnet/demo设计验证，但不得把“金额小”当作已审计或主网公众收款安全的证明。Arc Microgrants的主网要求不降低安全责任。
