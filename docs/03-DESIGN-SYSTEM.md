# 03 · 视觉系统与组件规范

这是 ArcBox 的拟定视觉基线，不是用户已逐页批准的效果图。目标：工具网站的清晰度、消费级付款页的易读性、业务后台的可操作性。采用浅色模块化布局，轻量磨砂只用于导航/浮层；资金规则正文使用不透明实底。

2026-09-23 M1-A：用户从三张方向图选择了“任务搜索优先”首页；四类页面的[响应式视觉基准与 QA](validation/M1-A-STATUS.md)已在独立原型中形成，待 `dev → main` PR 审查。它确认设计方向，不代表正式网站已实现或部署。

## 1. 视觉 token

| 类别 | 基线 |
|---|---|
| 背景/表面 | canvas #F7F8FA；surface #FFFFFF；muted #EEF1F5 |
| 正文 | text #17212B；secondary #56616E；border #DCE2E8 |
| 主色 | accent #2557D6；hover #1D46AD |
| 状态 | success #18794E；warning #8A5700；danger #B42318；颜色必须搭配文字/图标 |
| 工具识别 | Deliver 蓝、Group 紫、Split 青、Attend 橙、Milestones 靛、Rewards 绿；只用于图标/轻底，不把整个页面染色 |
| 字体 | 系统 Latin sans + PingFang SC/Microsoft YaHei；代码/地址 monospace；数字 tabular-nums |
| 字阶 | hero 40/48，页标题 28/36，区标题 20/28，正文 16/24，辅助 14/20；避免关键条款小于 14px |
| 间距 | 4/8/12/16/24/32/48/64；页面主要使用 24、32 |
| 圆角 | input 10，card 16，dialog 20；标签圆角不把所有控件做胶囊 |
| 阴影 | 仅悬浮元素或可操作卡片轻阴影；不要卡片套卡片 |
| 动效 | 120–200ms 的 opacity/transform；禁止资金确认时烟花掩盖下一步 |

所有配色须在实际页面检查对比度；不是写出色号即代表通过无障碍验收。设计目标为 WCAG 2.2 AA，正式检查参考 [W3C 标准](https://www.w3.org/TR/WCAG22/)。

## 2. 网格与布局

桌面内容最大宽度 1200px，左右至少 32px。工作区侧栏 224px；主区不小于 0，避免表格撑开整个页面。表单主区 640–720px；右侧规则摘要 320px。公共付款页内容 720–960px，不沿用全套管理员导航。

断点：<640 单列；640–1023 两列目录/顶部抽屉；≥1024 三列目录/固定侧栏。首屏需看到用途和至少一个主动作；不是整屏品牌插画。

## 3. 核心组件

| 组件 | 内容与行为 |
|---|---|
| ToolCard | 图标、用途、任务句、状态、一个 CTA；不可只有英文代码名 |
| ToolStatus | Live/Testnet/Preview/Paused 明文；由环境清单驱动，不手写“已上线” |
| Money | 显示 USDC 与金额；业务最多6位，常规2位；微额不能四舍五入成0而隐藏，hover/详情显示精确值 |
| RuleSummary | 收款方、金额、成功条件、退款条件、结算时间、费用、判定人；默认显示最重要4项，可展开完整规则 |
| Address | 前6后4 + 完整复制/查看；确认资金接收人时提供完整地址，不能只靠昵称 |
| Stepper | 选用途/填规则/预览发布；工具内步骤可更多但保存与返回一致 |
| TxProgress | 待授权、待付款签名、已广播、链上确认、业务处理中、完成；单独显示 txHash |
| ActionPanel | 当前能做什么、谁应操作、截止时刻、一个主按钮；每次刷新核验权限 |
| Timeline | 业务时间线与链上证据，区分用户提交、后台确认、链上完成 |
| StateBanner | 网络错误/索引落后/暂停/只读；给可恢复动作，不能只用红色 toast |
| EmptyState | 解释原因 + 下一步，不生成虚假统计图 |
| PermissionNotice | 展示仅 owner/买家/受益人/仲裁方能做什么 |
| ConfirmDialog | 标题用动作动词，显示精确金额、接收方、不可撤回影响；删除草稿和资金释放不共用弱确认 |
| RuleDiff | 发布新版本前对比金额、接收方、时间、分账、文件哈希；变化高亮 |

## 4. 表单原则

金额输入使用十进制字符串；禁止科学计数法、负数、多于6位小数；不静默截断。百分比显示两位，底层 bps，总和必须10000。日期选择同时显示本地时区及 UTC，不用“明晚”代替精确截止时间。地址校验网络/零地址/角色，校验成功不是资金安全保证。

字段错误在字段附近，顶部错误摘要能聚焦到首个问题。服务端保留用户输入；重新连接钱包不能清空整个草稿。不可变字段展示锁定原因并提供“复制为新版本”，而不是悄悄禁用。

## 5. 交易交互

主 CTA 示例：“授权 15 USDC”→“支付 15 USDC”。授权和付款分开，精确 allowance 默认，不自动无限授权。金额不足区分支付本金不足与预估 Gas 余量不足；同一 USDC 余额不可重复相加。

钱包拒签：中性提示“你已取消签名，尚未付款”。广播后：禁用重复创建订单，允许检查状态。失败时必须显示是否可能已经上链；无法确定时先核验，不立即重发。成功后主动作切换为“查看文件/查看报名/查看凭证”，不能继续显示支付按钮。

## 6. 双语文案

| 中文 | English |
|---|---|
| 浏览工具 | Explore tools |
| 创建链接 | Create a link |
| 待你处理 | Needs your action |
| 本金可退，网络费用不退 | Principal refundable; network fees excluded |
| 已确认付款，交付处理中 | Payment confirmed. Preparing access. |
| 可领取，不代表已经到账 | Available to claim, not yet received |
| 暂未核验，请勿重复付款 | Not yet verified. Do not pay again. |
| 仅演示，不涉及真实资金 | Demo only. No real funds. |

所有日期/数字按 locale 格式显示但底层精度不变。专业名词放帮助提示，不把 USDC allowance、Merkle root、nonce 作为普通用户的主要文案。

## 7. 无障碍与状态要求

键盘完整操作、可见焦点、弹窗焦点锁定与返回、label/aria-describedby、错误播报、图标按钮有名称。触控主按钮建议至少44×44px。减少动效时取消位移动画；减少透明度或低端设备时磨砂变实色；深色模式后续实现但不得简单反色破坏状态语义。

页面加载骨架不伪造精确数字。倒计时需附绝对日期；屏幕阅读器不每秒播报。提醒不能只靠颜色，活动满额/资格不符需要文字。成功反馈不自动跳转到用户看不到退款条件的页面。

## 8. 视觉交付门禁

实现前确认四类基准：工具首页、创建向导、公共付款页、工作区详情。每类至少375/768/1440宽检查。历史宣传拼图仅用于概念交流，不构成本包逐像素设计目标。没有真实渲染检查，不能声称视觉 QA 通过。
