# 04 · 页面与关键状态规格

本文件定义全站页面；每工具字段与状态机见对应工具文档。示例均为合成数据。英文短名是内部产品标识，中文页面优先展示用途。

P01、P09、P12/P13 与 P07 的首批[桌面/平板/手机视觉基准](validation/M1-A-STATUS.md)在 M1-A 独立原型中检查。[M1-B 网站骨架](validation/M1-B-STATUS.md)实现了无资金目录、六工具详情、演示向导、付款预览和本地草稿记录；下表完整页面与业务状态仍是后续实现要求，不因骨架存在而标记完成。

## 2. P01 首页详细结构

导航下方不放全屏大图。标题区高度约180px，任务搜索下方直接展示六工具卡片。每张卡片含一句具体场景，例如 Deliver：“卖一份模板，付款后开放文件”；Group：“人数够了才开班，不够可退款”。

卡片应能回答用途而不是技术实现。脚注说明 USDC、网络费、公开链记录；“连接钱包”不是唯一主 CTA。移动端首屏至少展示定位和前两项工具，完整六项不放在横滑里隐藏。

## 3. P09–P11 创建与发布

三段共享结构：基础信息→业务规则→预览发布。每工具复杂设置在自己的步骤中展开。右侧摘要实时更新，但敏感收款地址变化必须显式复核。底部有保存草稿、上一步和主动作，离开页面检测未保存。

发布清单：名称/公开说明、金额/币种、规则时限/时区、退款路径、受益人、分账协议、文件版本或名单根、谁判定线下事实、平台费、Gas、真实或Demo环境。与现有链上版本不符时拒绝发布，不能用新文案覆盖旧规则。

成功页显示“页面已发布”与“合约已确认”各自状态；合约部署广播不等于页面交易可用。复制链接与查看公开页优先，不用自动弹分享弹窗。

## 4. P12–P14 付款与记录

付款面板固定展示工具、订单、付款账户、网络、收款合约、金额、预估费用。批准与付款各自独立 txHash；approve 成功不出现购买成功图标。

确认后分支：Deliver 显示文件准备/可访问；Group 显示付费席位与成团日期；Attend 显示签到与取消期限；Milestones 显示阶段已入金等待交付。Split/Rewards 的“可领取”只在实际转出成功后变成“已领取”。

/r 页面访问控制按真实付款人/受益人核验，不以知道随机 URL 当全部权限。公开摘要不展示邮箱、商品私有文件名、仲裁证据。重要规则可在付款前查看且付款后固定。

## 5. 管理后台不做财务幻觉

P07 主要区域是“待处理”：待验收、交付失败、可结算、待回复争议；次要区是最近项目。指标只显示真实分类：锁定本金、退款负债、已结算收入、已领取金额；不同分类不能同时累计成总收入。

订单行操作基于链上状态计算，不根据按钮上一次点击决定。API拒绝时保留上下文，并提示“状态已变化，已刷新”。危险操作（取消成团、仲裁分配、没收提议）需要完整后果预览，不能只“确认吗”。

## 6. 工具专用页面的强制信息

| 工具 | 页面不能省略的信息 |
|---|---|
| Deliver | 文件规格/版本、交付超时、无条件退款窗口、网络费不退、内容无法防复制 |
| Group | 门槛是付费席位不是独立人数、何时最终判定、何时款项释放、成团不证明履约 |
| Split | 比例总和、每人钱包、舍入余数归属、哪些收入进入本协议、不可追溯改比例 |
| Attend | 签到核验者、缺席不是立即扣款、异议窗口、仲裁方与超时全退 |
| Milestones | 当前阶段金额、交付/验收时间、默认验收规则、争议方、超时兜底比例 |
| Rewards | 哪个钱包有资格、领取期限、需要Gas、未领取余额到期归谁、名单公开性边界 |

## 7. 异常文案示例

“你已付款，无需再次支付。正在核验文件访问。”
“报名已满，交易未成功；本金未扣取，网络费用可能已产生。”
“这笔金额仍处于退款期，暂不能分账。”
“组织者提出未到场记录。请在 2026-10-03 12:00 UTC 前提交异议。”（示例日期，不是实际活动）
“领取期限已过，合约不能再发放本期奖励。”
“链上记录已确认，但通知未发送。重试通知不会重复付款。”

## 8. 页面验收

所有32类页面都有 loading/empty/permission/error/success 中适用的状态，不以一个全局 toast 替代。P15、17、19、21、24、27 必须覆盖375px、钱包切换、错误网络和重载恢复。金额/签名/时限文本不得被截断；所有高风险动作必须可返回查看原始规则。
