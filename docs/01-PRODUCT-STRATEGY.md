# 01 · 产品策略与需求设计

## 1. 产品问题

小型线上业务常把收款、报名、文件交付、退款、分钱放在不同工具或聊天记录里。ArcBox 的产品假设是：对本来愿意使用 USDC 的人，一套以用途组织的工具能减少人工核对和追问。**这是待用户访谈与试用验证的假设，不是现有客户调研结论。**

ArcBox 不试图让不使用稳定币的所有人迁移支付方式。首批目标是已有对手方、已有商品/活动、愿意使用 Arc USDC 的小额业务；不承担找客户、找工作、内容分发或需求撮合。

## 2. 用户与任务

| 人群 | 触发事件 | 原本的操作 | ArcBox 的结果 | 是否为付费决策人 |
|---|---|---|---|---|
| 数字创作者 | 准备出售素材包 | 私聊收款、截图、手动发文件 | 一个商品链接与购买记录 | 是 |
| 工作坊组织者 | 不确定是否够人开班 | 表单意向、催款、失败后退款 | 付费席位与明确成团/退款结果 | 是 |
| 合作者 | 一起出售商品 | 一人收钱，月底补表转账 | 所有人查看固定比例及可领取额 | 一般是 |
| 活动组织者 | 免费活动经常缺席 | 报名表和人工追踪 | 保证金、签到与有申诉的处理 | 是 |
| 自由职业双方 | 确定分阶段项目 | 聊天约定、预付款、催尾款 | 当前阶段有资金，验收规则可查 | 共同决定 |
| 社区运营 | 已有明确奖励名单 | 收地址、核名单、批量发送 | 自助资格查询与一次性领取 | 是 |
| 参与者/买家 | 收到链接 | 问能否付款、到账没有 | 看规则、付款、获得权益或退款 | 否，不能被迫注册商家后台 |

## 3. 三层产品

**工具层：**六个独立目的入口，用户不必购买整套系统。**共享业务层：**工作区、草稿、规则版本、参与记录、通知、审计日志。**资金层：**每个实例明确自己持有哪些负债、谁能领取、何时释放。

组合不是自由拖拽资金逻辑。v1 只允许白名单组合：Deliver→Split；Group→交付权限→Split；Milestones 已放款阶段→Split（后续）。Attend 的应退保证金和 Rewards 的未领取奖励不允许接 Split。

## 4. 价值表达

首页：“你的链上实用工具箱”。辅助说明：“收款、交付、分账、报名与奖励，选择工具就能开始。”避免“革命性金融基础设施”“无信任保证”“自动解决纠纷”等承诺。

每个工具详情必须同时解释：谁使用、三步流程、一组具体示例、需要的钱包/资金、退款与费用、依赖谁做判断。不能只给技术词和走势图。

## 5. 范围分层

| 层级 | 内容 |
|---|---|
| 必须设计完整 | 全站 UX、六工具生命周期、异常流程、资金与权限、Cloudflare 架构、测试 |
| 首个可用里程碑 | 独立 Split、Deliver、Group；一个真实组合场景；双语关键路径 |
| 六工具完整版本 | 补充 Rewards、Attend、Milestones；完整角色、恢复和争议流程 |
| 暂不做 | 内置交易市场、钱包托管、法币出入金、跨链桥、贷款收益、无限多资产、AI 仲裁、自动报税、第三方插件市场 |

平台费试运行设为 0 并写入版本；显示“平台费 0，网络费用另计”，不能写成所有服务永久免费。未来收入假设为工作区订阅、品牌页面、较大存储/报表额度，不以没收保证金或挪用未领取本金为收入。

## 6. 用户研究计划与淘汰标准

每个方向先访谈 3–5 位实际处理过对应业务的人，询问最近一次过程、频次、资金损失/工时、现有工具和迁移障碍；这只是研究计划，不是已完成访谈。要求演示一份脱敏账单/活动流程，而不是只问是否喜欢想法。

可用性测试给出任务：“发布 15 USDC 的模板”“创建 10 席位成团”“找到你的退款”。记录能否无帮助完成、误解资金规则的位置、钱包连接放弃点。目标：首次用户能在不读开发文档的情况下说明何时能拿回钱。

放弃或缩小范围的信号：用户愿意换回原工具避免入金 Arc；需要大规模获客才能成立；没有任何组织者愿意下一次再用；核心价值仅仅是新增 USDC 支付按钮。

## 7. 产品指标

北极星建议：**真实工作区在第二次独立业务中完成结算或退款的比例**，不以免费奖励领取数当付费需求。

漏斗：tool_view → draft_created → rules_previewed → published → first_funding → business_resolved → repeat_project。另记录创建耗时、确认后权益可用延迟、退款成功率、索引积压、失败恢复工单数。demo/testnet/内部钱包必须排除于真实增长指标；未经授权不把钱包、电子邮件发到第三方分析平台。

质量目标是设计验收标准，不是 SLA：关键表单在 375px 可用；正常链路可恢复；支付成功后不需要用户反复提交；任何资金都有明确状态和退出条件。

## 8. 上线责任

不得把“资金在合约里”当成法律免责。商品权利、退款义务、仲裁安排、制裁/地区限制、个人信息处理及平台责任需要具体业务审阅。未确定实际责任人和政策前，不开放大额或公众资金入口。

正式支持渠道和域名尚未提供，不使用虚构客服邮箱。版权、隐私、举报、风险说明须在发布前有真实可用的入口。
